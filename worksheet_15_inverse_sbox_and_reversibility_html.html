Quick Reference — tap to expand
Inverse lookup rule: If \(S(x) = y\), then \(S^{-1}(y) = x\). The inverse S-box is the forward S-box table read backward.
Internal order: Forward: field inverse \(\to\) affine transformation.
Inverse: inverse affine first, then field inverse again.
Round-trip: \(S^{-1}(S(x)) = x\) for every byte \(x\).
Bijection: AES S-box maps 256 inputs to 256 distinct outputs — no duplicates. Any duplicate output would break decryption.
Key examples: \(S(\texttt{0x00})=\texttt{0x63}\), so \(S^{-1}(\texttt{0x63})=\texttt{0x00}\).\quad \(S(\texttt{0x53})=\texttt{0xED}\), so \(S^{-1}(\texttt{0xED})=\texttt{0x53}\).

Part E — Conceptual questions

E1 sample. AES decryption must reverse every step that AES encryption applied in order to recover the original plaintext. The SubBytes step in encryption uses the S-box to substitute each byte. Decryption must undo that substitution — which requires applying the inverse S-box (InvSubBytes) to each encrypted byte to recover the pre-substitution byte.

E2 sample. The field-inverse step alone is involutive: taking the inverse twice returns to the original. But the AES S-box also applies the affine transformation after the field inverse. The composition is: field inverse → affine. Undoing that composition requires: inverse affine → field inverse. The full S-box is not the same function as the inverse S-box because of the affine step in the middle.

E3 sample. The inverse S-box receives the output \(y\) and must produce the original input. If both \(a\) and \(b\) map to \(y\), the inverse S-box cannot know which of the two was the actual input — the information is destroyed. Any ciphertext byte equal to \(y\) would have two equally valid decryptions, making recovery impossible.

E4 sample. Think of the S-box as a special lock. You put a key in (the input byte), turn it, and the lock produces a code (the S-box output). The inverse S-box is the matching key that, when given the code, tells you exactly which key was used. No matter which key you started with, the lock-and-unlock process always returns the original key. That is the round-trip property: encrypt-then-decrypt gets you back where you started, every single time.
